## Reference precedence

The optional original project is `games/CC3Proj/{replicationId}_UI`, where `{replicationId}` is the target `slot-fe-{slug}` identifier. This current rule takes precedence over any historical step wording that names `metadataGameId` for the original-project directory. `metadataGameId` remains provider/wire metadata only.

## Original behavior and acceptance baseline

Infer original logic primarily from the target project's `doc/js_scripts/` and `assets/resources/{replicationId}_res/` (`{gameId}_res` in user requests). When present, also inspect the read-only original project `<slot-fe-client-root>/games/CC3Proj/{replicationId}_UI/` (`CC3Proj/{gameId}_UI`) as a reference source for its original resources and code state. Resolve `{gameId}` from the target `slot-fe-{slug}` directory as `replicationId`; keep `metadataGameId` from `doc/project_info.md.gameId` as provider/wire metadata only. If this project is absent, empty, or not safely inspectable, record `originalProject.status = NOT_FOUND_IGNORED` and continue without it. Do not make the optional project a prerequisite for the target-local resource/script evidence minimum. When it is used, cite files with `kind: original-project` and a games-root-relative source such as `CC3Proj/{replicationId}_UI/assets/...`; keep the source read-only and never copy its serialized bindings blindly into the target. Read relevant archived JS when available to trace entry conditions, state transitions, animation/audio sequencing, completion callbacks, and cleanup; cross-check Prefab bindings, serialized defaults, animation tracks, Spine, and audio resources. Record file/symbol evidence and distinguish directly proven behavior from inference and unresolved gaps. A missing script is not a blanket blocker when resources prove the required behavior; an essential unresolved behavior returns `NEEDS_LOCAL_REFERENCE`.

### Target-local PNG reference policy

Treat target-project files matching `doc/**/*.png` as optional competitor-image references by default. When present, they may inform visual style, composition, relative layout, color, scale, and asset-appearance decisions, and should be cited as optional visual evidence. They do not prove protocol, symbol IDs, payout, server semantics, state transitions, animation timing, audio, callbacks, cleanup, or runtime parity; cross-check those claims against target-local resources/scripts, runtime evidence, and the raw server contract. Missing, unreadable, or insufficient PNGs must never trigger `NEEDS_LOCAL_REFERENCE`, `NEEDS_PROJECT_INFO_INPUT`, `DIRTY_FILE_CONFLICT`, or another exit/blocking status. Do not stop because these files are absent, and do not claim visual acceptance from PNGs alone.

Do not use a competitor URL for visual acceptance or request external competitor screenshots, live sampling, or URL access to resolve behavior gaps. `competitorUrl` remains identity metadata only. Validate the target client's implementation against the locally derived behavior through Cocos/runtime state, deterministic fixtures, logs, and target-client screenshots as appropriate. Static checks or source-based inference alone do not prove runtime/visual acceptance. This baseline also governs `s_cli` contributions dispatched by `s_init`; external screenshot coverage and optional target-local PNG coverage are not `s_cli` acceptance Gates.

## Server data and symbol immutability

At runtime, the accepted server response is the sole source of truth for symbols and outcomes. Preserve the raw response/fixture as an immutable artifact and consume its symbol/layout fields (for example `rl`, `orl`, `rns`, `snwm`, encoded cells, `ptbr`, and `d`) exactly as the verified runner contract defines them. The client may parse, clone, perform a contract-defined lossless decode, map values to views, and derive presentation-only state; it must not mutate the server payload or silently change its meaning.

Never replace symbol IDs, reorder/pad/truncate cells, synthesize/move/remove/merge/split symbols, change multipliers/payouts/special markers, or overwrite mapper/fixture values merely to make the client render or pass a check. If the server response is malformed or contradicts the runner contract, stop with `INVALID_SERVER_RESPONSE` or `NEEDS_PROTOCOL_EVIDENCE`; if the verified response is valid but the mapper/client cannot consume it, stop with `CLIENT_CONTRACT_GAP`. Any server-data change belongs to the server workflow and is outside `s_cli`. Acceptance must compare the raw server symbol data with the mapped/runtime state and record that no semantic mutation occurred.

## Elimination effect and Symbol animation rule

When replicating elimination behavior, ordinary Symbol nodes/render layers must remain above the elimination-effect layer so the effect does not cover ordinary Symbols that are not targets. A Symbol selected for elimination should generally play its corresponding type/resource animation, such as break or pop, and the animation completion callback must participate in the clear barrier before Drop or refill begins. Confirm the animation owner, clip/Spine state, timing, audio, callback, and cleanup from target-local resources, archived JavaScript, and target runtime evidence; record UNKNOWN or a Gate when the target proves an exception.

For Spin peeking, the default column-effect order is Reel background < Spin column effect < Symbol. The column effect must cover only its intended column and must not cover the Symbol layer; verify the actual sibling/layer/z-order in the target resource and runtime. A different order requires target-local resource, archived JavaScript, or runtime evidence and an explicit exception.

`browser:control-in-app-browser` skill, or substitute another browser-control wrapper. This

verify it; HTML media-element muting alone does not cover WebAudio. If muting is unavailable,
fails, or cannot be verified, continue navigation, interaction, and acceptance without requiring
confirmation. Muting must not be a prerequisite, exit condition, or acceptance blocker; do not
return `NEEDS_CHROME_MUTE` for this workflow.

Track every page and popup created by the task. In a cleanup-safe `finally` path for success,
failure, timeout, and blocked exits, stop any active trace and save required evidence, close
all task-owned pages in reverse creation order with `close_page`, then close a dedicated

with `list_pages`. Never close baseline pages or terminate Chrome by broad process name. If the

identity and do not claim browser acceptance or cleanup success.

## Cocos MCP endpoint discovery

Before any Cocos Editor, Scene, Console, or Preview call, inspect the target project's `funplay-cocos-mcp.config.json`. A valid non-empty `host` and integer `port` from `1` through `65535` are the target-local source of truth for that client's MCP endpoint; initialize directly at `http://{host}:{port}/`. Do not assume `8765`, reuse a port from another game, or treat a global `funplay_cocos` wrapper endpoint as evidence for the target client.

The file establishes a configured endpoint only; it does not prove the service is reachable or that it serves the target project. After initialization, verify the returned project identity against `slot-fe-{replicationId}` before using its logs, scene state, or screenshots as runtime evidence. If the file is missing or malformed, record `NOT_FOUND` or `INVALID`, then use `cocos-mcp-workflow` discovery as a fallback without making the configuration file itself an exit condition. An unreachable configured endpoint or a project-identity mismatch leaves Cocos runtime/visual acceptance pending; preserve non-MCP evidence and never substitute another project's endpoint.
